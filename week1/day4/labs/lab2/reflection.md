# Reflection
This sprint kept us on our toes. We had to tweak the Sprint Backlog more than once, but we never lost sight of what mattered: giving developers real tools to monitor, track, and dig into CI build statuses. The first hurdle was the old, half-baked CI API docs. We didn’t just stall out. Instead, we split up—Farida dove in to figure out the real API endpoints and map the data, while Mahammad kept building out the dashboard UI with mock data so we wouldn’t lose momentum. Then came the curveball: a stakeholder wanted email notifications. We talked it over and made a call—it didn’t fit this sprint’s goal, so we parked it in the Product Backlog for later.

What kept us moving was having clear anchors: the Sprint Goal, our story priorities, and a realistic sense of our own bandwidth. Right at the end, we hit a nasty filter bug during testing. So we shifted gears again, added a task to fix it, and focused on finishing the stories that really mattered—Build Status Display and Build Details View—instead of spreading ourselves thin on extras. That felt like the right call. Get the essentials working first, then polish later.

Daily Scrums actually made a difference this time. They forced us to be open about problems right away. When something blocked us—like those API headaches or filter logic not lining up—we brought it up fast and adjusted our plan on the fly. That openness saved us from those last-minute disasters and made it easier for me, as Scrum Master, to clear the path.

Sticking to our Definition of Done kept quality high. Peer reviews and unit tests before calling a story “done” made the demo run a lot smoother. Sure, we still felt the tug-of-war between speed and quality, especially as the deadline got close, but holding the line on DoD stopped us from shipping half-baked work.

The Sprint Retrospective gave us some clear next steps. We agreed to set up a mid-sprint backlog refinement meeting, put together a simple DoD checklist, and start a shared CI API doc so we’re not confused next time. One thing we did well? Courage. We stood our ground on mid-sprint changes and owned up to anything that wasn’t ready. That protected our focus and helped us deliver something solid.
